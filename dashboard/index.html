INT4 Sub-Byte Packing & Sign Extension

Pack two 4-bit nibbles into 1 uint8 byte & reconstruct with 2's complement

Computer memory architectures are byte-addressable (8-bit minimum). To store INT4 weights, the engine packs pairs of 4-bit nibbles: packed_byte = (high_nibble << 4) | (low_nibble & 0x0F)

Sample 4-bit Array [-8 to +7]:

-8 +7 -3 +2 0 -1 +5 -6
⬇ Sub-Byte Bitwise Packing ⬇

Packed uint8 Bytes (50% Storage Reduction):

0x78 (120)
High: 7 (0111) | Low: -8 (1000)
0x2D (45)
High: 2 (0010) | Low: -3 (1101)
0xF0 (240)
High: -1 (1111) | Low: 0 (0000)
0xA5 (165)
High: -6 (1010) | Low: 5 (0101)
Two's Complement Sign Extension on Unpack: 
q = (raw_nibble >= 8) ? (raw_nibble - 16) : raw_nibble

Critical Architectural Formulations:

  1. Decoding is Strictly Memory-Bound: At batch size $M=1$, every generated token must stream the entire weight matrix ($I \approx 1\text{--}4\text{ OPs/Byte}$). Faster ALUs do not accelerate generation; only quantization cuts memory bus traffic to produce a $4\times$ speedup!
  2. Prompt Prefill is Strictly Compute-Bound: With $M=512$ tokens, weights are reused across vectors ($I > 400\text{ OPs/Byte} \gg I^*$), pushing execution to the flat compute ceiling where Tensor Cores dominate.
